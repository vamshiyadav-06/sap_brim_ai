## Production deployment (2026-11-04)

`DEPLOYMENT.md` is the server guide. `docker-compose.prod.yml` (Compose project `sap_brim_prod`, separate volumes `pgdata`, `caddy_data`, `caddy_config`) runs `postgres` (not published), `backend` (`backend/Dockerfile`, build context = repository root with an allowlist `.dockerignore`; CPU-only torch, embedding + RapidOCR models baked in, `HF_HUB_OFFLINE=1`, user `app` with `APP_UID` default 1000, CMD runs `alembic upgrade head` unless `RUN_MIGRATIONS_ON_START=false`, then one uvicorn worker; bind mount `./knowledge_base`) and `web` (`frontend/Dockerfile`: node:22-slim build, then `caddy:2-alpine` with `frontend/Caddyfile`). The server `.env` comes from `.env.example` and sets `COMPOSE_FILE=docker-compose.prod.yml`, so plain `docker compose` uses the production file there. Restoring a development dump: `pg_dump -U sap_brim_ai` on the source, `pg_restore -U "$POSTGRES_USER" --no-owner --role=sap_brim_ai --no-comments --exit-on-error` into the init-created empty database (rehearsed on a scratch database 2026-11-04).
